# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Laravel 12 app that is two things at once:

- **The public site of Creatium Lab** (a two-person agency for small Bulgarian businesses: website build and monitoring, GEO/SEO, email campaigns), live at creatiumlab.com. Bulgarian is the main language (root URLs); an English version lives under `/en`.
- **An internal admin panel** (`/admin`) for managing client projects. It started as a university "project management system", which is why the core model is `Project` with `Category` / `Technology` and roles `admin` / `project-manager` / `developer`.

The admin is in Bulgarian (`lang/bg.json` and `lang/bg/pagination.php` for pagination). Its menu (`admin/layout`) is grouped Клиенти / Продажби / Сайт / Настройки, with badges for unread inquiries and call-backs due today. The dashboard (`AdminController::dashboard`) shows what needs doing today: unread inquiries, calls today against the goal (`OutreachCall::todayStats()`), first emails sent today against the limit, Крео chats in the last 7 days, the latest leads with `tel:` links, consultations in the next two weeks, projects in progress, the next scheduled blog post and leads by channel. Project statuses are stored in English (`Planning`, `In Progress`, `Completed`, `On Hold`, `Cancelled`, validated that way) and shown through `Project::STATUSES` / `statusLabel()` / `statusClass()`; `serviceLabel()` turns a `contact_topics` key into its text. **Sales pipeline**: website leads (contact form, Крео, website check) get a `stage` (`Project::STAGES`: new → contacted → offer → won / lost, set to `new` on create; `OPEN_STAGES` are the first three), `stage_changed_at`, a `next_action` text with `next_action_at` (stored UTC, entered in Sofia time) and a `lost_reason`. `partials` `admin/projects/_pipeline` (on inquiry cards, the project page and **Днес**) PATCHes `admin.projects.pipeline`; won moves a `Planning` project to `In Progress`, lost sets `Cancelled`, both clear the next step. **Днес** (`/admin/dnes`, `TodayController`, `App\Support\Admin\Today`) is the first menu item and where login lands: consultations today/tomorrow, unread leads with how long they wait, next steps due today or overdue, prospects who clicked in the last 7 days, and open leads without a next step; its badge counts unread + due + call-backs. Leads can be assigned (`projects.assigned_to`, „Води го“ in the pipeline panel); Днес has „Моите и неразпределените“ (`?mine=1`) and the project list a „Моите“ filter. **Search** (`/admin/tarsene`, `Admin\SearchController`, box in the header, Ctrl+K): leads/projects, prospects, calls, Крео chats and posts; phones match on digits (last 9). **Phone**: a bottom menu (Днес, Запитвания, Обаждания, Търсене, Меню) below `md`, and `public/admin.webmanifest` (start `/admin/dnes`, icons `images/icon-192/512.png`) so the admin can be added to the home screen. The next-call screen takes keys 1–4 (result), Enter (save and next), S (skip), B (back). **Здраве на системата** (`/admin/zdrave`, `Admin\HealthController`): mail, Telegram, outreach mailbox, Serper, Reoon, Крео provider, Facebook, GTM, monitored client sites, debug mode, URL, last build, free disk, storage, last backup in `/var/backups/creatium`, each with the command that fixes it. The dashboard shows a red banner for overdue steps. **History** (`project_notes`, `ProjectNote`: note / call / stage): the pipeline panel takes an optional call note and logs stage and next-step changes; the project page has an „История“ form and a timeline built by `ProjectController::timeline()` (creation and channel, notes, `client_emails`, the Крео chat by `lead_id`, a linked prospect's first email and clicks). **Converting** (`App\Support\Admin\LeadConverter`): „→ Запитване“ on a prospect (`admin.outreach.lead`) or a call (`admin.outreach.calls.lead`, also on the next-call screen) creates a `Project` with `source = 'outreach'`, stage `contacted`, channel „Писма до бизнеси“ / „Обаждания“ and the contact details, and links it back (`project_id` on `outreach_prospects` / `outreach_calls`; a second click opens the same lead). Prospects now store the business `phone` from the map search. **Subscriptions** (admin **Абонаменти**, `/admin/abonamenti`, `Admin\ClientController`): a project with `monthly_fee` > 0 (and not Cancelled) is a subscriber (`Project::subscribers()`), with `package` and `billing_day` set in the project form. `client_payments` (one per `period` „YYYY-MM“) and `Project::paymentState()` (Sofia time; paid / upcoming / late, an unpaid previous month counts as late) drive the page (monthly revenue, paid this month, late, „Платено за …“ = `admin.clients.paid`, which also writes a note), the menu badge, Днес and the dashboard revenue. **Site monitoring** (`App\Support\Admin\SiteMonitor`): subscribers with a `website_url` are checked at most every 6 h (response via `SiteChecker::fetch()`, SSL expiry from the certificate, domain expiry from RDAP, none for .bg) by the `MonitorClientSites` web middleware (one tick per 15 min after the response, up to 3 sites; no cron) or `php artisan creatium:monitor-sites [--all]` / „Провери сега“; results go to `monitor_*`, `ssl_expires_at`, `domain_expires_at`, problems (down, SSL or domain within 14 days) show on Абонаменти and Днес, and Telegram gets an alert when a site goes down and at most once a day while a problem lasts. **Monthly report**: the `monthly-report` template in Имейли до клиенти (done / results / site status / next month, one item per line), linked from each subscriber with the site status pre-filled. `<x-phone>` (`App\Support\Phone`) renders a `tel:` link plus Viber and WhatsApp links in the 359… format. **Telegram** (`App\Support\Notify\Telegram`, `services.telegram.*` = `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`, set by `php artisan creatium:telegram-connect`, guide in `tools/telegram/README.md`; `.env` writing shared with Facebook in `App\Support\EnvFile`) gets new leads (form, Крео, website check, with the consultation time) and a prospect's first click (plus any booking click), sent after the response; without settings nothing is sent. The project list has the filters Отворени запитвания (open stages, by next step) / В работа / Завършени (`?filter=leads|active|done`), and its search also matches the client's phone and email. The project page shows the client's phone, email, site and consultation at the top, and the edit form has client phone and email fields.

The two halves meet in one place: **a contact-form submission becomes a `Project`** (`source = 'website'`, status `Planning`, category "Ново запитване"), so leads show up in the admin list next to real client work.

Visual and copy rules live in `DESIGN.md`; read it before touching views or text. The site follows a technical specification from the marketing partner (Владимир Цончев); GTM + Consent Mode, BG/EN and the CMS (blog, editable texts, per-page SEO) are all built.

## Commands

```bash
composer install && npm ci          # dependencies
npm run build                       # Vite build -> public/build (Tailwind v4)
php artisan test                    # full suite (SQLite in memory, see phpunit.xml)
php artisan test --filter=test_contact_form_creates_lead_and_notifies_team   # one test
php artisan test tests/Feature/MarketingTest.php                              # one file
php artisan migrate:fresh --seed    # local: also seeds demo users + demo projects
php artisan creatium:make-admin you@example.com --name="Name"   # create/promote an admin
```

Local DB: set `DB_CONNECTION=sqlite` and `DB_DATABASE=<abs path>/database/database.sqlite` in `.env`. Demo logins (local/testing only): `admin@projectmanager.com` / `password`.

`npm run dev` (and `composer dev`, which runs it) writes `public/hot`; while that file exists `@vite` points at the dev server and the built CSS is not used. Never leave it on a server (`deploy/deploy.sh` deletes it).

CI (`.github/workflows/tests.yml`) runs `php artisan test` on PHP 8.2/8.3/8.4 after copying `.env.example` (`composer.json` pins `config.platform.php` to 8.2.0, so `composer update` never locks a package that needs a newer PHP); tests call `withoutVite()` (see `tests/TestCase.php`), so no build is needed for tests. `.github/workflows/security-audit.yml` runs `composer audit --locked` and `npm audit` every Monday, on demand and when a lock file changes (separate from Tests, so it never blocks a deploy; a failure means: update the named package and run the tests). `.github/dependabot.yml` sets `open-pull-requests-limit: 0`, so Dependabot opens only security-fix PRs (when „Dependabot security updates“ is on in the repo settings).

## Architecture

**Routing** (`routes/web.php`): public pages are registered from one `$publicPages` map for both languages. Bulgarian uses Bulgarian slugs at the root (`/uslugi`, `/paketi`, `/proekti`, `/za-nas`, `/kontakti`, `/poveritelnost`, `/usloviya`, `/biskvitki`); English uses `/en/...` with English slugs and the same route names prefixed `en.`. In views always link with `lroute('services')` (from `app/helpers.php`), never `route()`, so links stay in the current language. Dynamic `/sitemap.xml` (both languages with hreflang alternates) and `/robots.txt` come from `PageController`. `/about` and `/contact` 301-redirect. In production `RedirectToCanonicalHost` (prepended globally) 301-redirects `www.` + the APP_URL host to APP_URL with the same path and query, and `AppServiceProvider` forces the root URL to APP_URL, so canonical/hreflang/sitemap never point at www (Nginx answers both hosts; Google had indexed www pages as duplicates). There is **no public registration**; accounts come from `creatium:make-admin` or the admin Users screen. Admin routes use `auth` + `admin` (`CheckAdminAccess`: any of the three roles); user management additionally needs `role:admin` (`RequireRole`). Login and the contact POST are throttled.

**Languages**: the global `SetLocale` middleware sets the locale to `en` when the first path segment is `en`, otherwise `bg` (this also covers 404 pages). Views wrap UI text as `__('Bulgarian text')`; `lang/en.json` maps it to English, and a test fails if a translation is empty or still Cyrillic. Long legal pages have separate English views in `resources/views/en/` (`PageController::localized()`). The layout outputs hreflang links and the BG/EN switcher for any route that exists in both languages. Leads record `locale`; admin and the notification email stay Bulgarian and always store the Bulgarian service label.

**Site content is data, not markup.** `config/creatium.php` holds contact details, hero and audience copy, services, `contact_topics` (the form's service dropdown), process steps, packages/prices, FAQ, team, industries, legal entity data, `gtm_id`, `google_site_verification`, the `cookies` list shown on `/biskvitki`, `inline_css` and `notify_email`. English versions of the content keys are in `config/creatium_en.php` (same keys; missing keys fall back to Bulgarian). Views read content through `site('services')`, never `config()` directly. `contact_topics` is keyed (`new-system`, `modernization`, `support`): the key is the form value, the label is per language. The home page reads the blocks `home_hero` (with `accent`: words of the title shown in color), `home_problem`, `home_engine`, `home_process`, `home_contact` and `home_trust` (the proof row under the hero, the engine diagram labels, „С кого работим“ (the „Не сме подходящи, ако“ box was removed at the owners' request in October 2026), the four principles, the demo-industries and blog intros; sections are numbered „01 / …“ in order). The proof row is a small label (`home_trust.proof_label`, „Готова система, не визитка“) over four equal columns from `home_trust.proof` (short value, one-line text, optional `link` that turns the text into a link), on one theme, the owners' copy from October 2026: Google + Meta ad tracking set up, enquiries straight to email/phone/CRM, self-editing, conversion-focused design; the Google rating appears only when `creatium.google_reviews` (`GOOGLE_REVIEWS_RATING` / `_COUNT` / `_URL`, copied by hand from the Business Profile) has a count. The latest three posts appear when the blog has visible posts in the current language; `/uslugi` reads `services_page`; `/paketi` reads `plans` (lines in `build_items` / `monthly_items` may start with "Title: ", shown bold); the FAQ page `/vaprosi` / `/en/faq` (`PageController::faq`, view `faq`, route `faq`, FAQPage JSON-LD, in the sitemap and `Content::SEO_PAGES`) reads `questions`, grouped by each item's optional `group` (topic list with anchors); the About page links to it. Each service also has its own page `/uslugi/{slug}` / `/en/services/{slug}` (`PageController::service`, view `service`, route `services.show`, `PageController::serviceUrl($key, $locale)`) from `service_pages` (keys `website`, `seo`, `google`, `email`, `support`; per language: slug, menu label, title, SEO title/description, lead, problems, includes, result, `package` = index into `plans.items`, optional note, FAQ rendered with FAQPage + Service JSON-LD); they are in the sitemap with hreflang pairs and linked from the `/uslugi` cards (`$cardPages` maps the card slugs). **Industry pages** „Изработка на сайт за …“ (`/izrabotka-na-sait-za-{slug}`, Bulgarian only, `PageController::industry`, view `industry`, route `industry`) come from `creatium.industry_pages` (restorant, kozmetichen-salon, zabolekar, avtoservis, stroitelna-firma, onlain-magazin: SEO title/description, lead, „Какво трябва да има сайтът“ list) and reuse the problems, solutions, package and FAQ of their demo (`demo` = slug in `demos`), with a demo screenshot, Service + FAQPage JSON-LD and the breadcrumb Начало › Изработка на сайт › page. They are in the sitemap (no hreflang) and `/llms.txt`, and linked from a „Сайт за:“ row in the Bulgarian footer, the website service page and each demo card on /proekti; the language switcher sends English visitors to the English website service page. The header menu is `Услуги ▾ · Пакети · Проекти · За нас ▾` plus a **Безплатна консултация** button to `/kontakti#konsultatsiya` (`$menu` in `layouts/public`; desktop dropdowns open on hover and on click/Esc via `[data-dropdown]`, mobile uses `<details>`); „Често задавани въпроси“ in the За нас menu goes to `/vaprosi`. `/paketi` shows each plan's audience, prices and only the bold heads of the items (text before ": "), with the full lines behind "Вижте подробно какво включва", so admin edits of `plans` keep working. These copies came from the owners in October 2026 under new keys, so older admin overrides of the retired keys (`hero`, `audience`, `home_sections`, `process`, `services`, `packages`, `faq`) stay in `content_blocks` but are no longer read. Change copy there first. Contact/legal values can be overridden by `CREATIUM_*` env vars (phones: `CREATIUM_PHONES`, comma-separated). Because production runs `config:cache`, read env only inside config files.

**Lead flow** (`HomeController@submitContact`):
1. Validates name, phone, email, `service` (the project status, one of `creatium.contact_topics`: `new-system`, `modernization`, `support`), an optional message, an optional `consultation` slot and a required `consent` checkbox. A hidden `website` field is a honeypot: if filled, the request fakes success and stores nothing.
2. Creates the `Project` lead (phone in `client_phone`, email in `client_email`, topic in `service`, the chosen slot in `consultation_at`), copying attribution from the session.
3. Sends `App\Mail\NewLeadMail` to `creatium.notify_email` (default `info@creatiumlab.com`) and stamps `email_sent_at`; a mail failure is logged, leaves `email_sent_at` empty and never loses the lead. Production `.env` starts with `MAIL_MAILER=log`: run `bash deploy/configure-mail.sh` once to switch to SMTP and `php artisan creatium:test-mail` to verify. The admin menu **Запитвания** (`Admin\InquiryController`) lists website leads with full messages, unread state (`read_at`) and a warning while the mailer is `log`/`array`.
   **Consultation booking** (`partials/booking`, inside the form, `#konsultatsiya`): `App\Support\Booking` offers `creatium.booking.times` on the next `days` working days from tomorrow (Sofia time, no holiday calendar), greys out slots already taken by another lead, and `resolve()` rejects anything else. With a slot, the client gets `ConsultationBookedMail` (with an "Add to Google Calendar" link) and the team email and the admin inquiry card show the time with the same link.
4. Flashes `success`, `lead_created` and `lead_service`; the next page pushes `{event: 'generate_lead', lead_service}` to the GTM dataLayer.

**Emails to clients** (admin menu **Имейли до клиенти**, `Admin\ClientEmailController`, routes `admin.client-emails.*`): templates are defined in `App\Support\ClientEmails` (`inquiry-reply`, `offer-start` for Стартов двигател, `offer-active` for Активен Маркетинг & Растеж; the owners' copy from October 2026; `demo-site` after a phone call: a „Вижте демото“ button to `demo_url` (field type `url`, validated as http(s), optional: without it the email says the demo is in the attached PDF, and `link_or_pdf` makes the send fail when there is neither link nor PDF), an optional „От разговора ни“ note, what to look at, a „this is a demo“ notice and next steps), each with a form field list; `{client_name}` and `{business}` in the subject are filled from the fields. Retired keys (`offer-biznes`, `offer-rastezh`) only keep a label for the send history. The views are `resources/views/emails/client/` (shared `layout`, table-based inline-styled HTML, prices in €; the logo is embedded as a `cid:` inline image when sent and loaded from the site in the admin preview). Mailables without their own text view (`ClientTemplateMail`, `NewLeadMail`, `ConsultationBookedMail`, `SiteCheckReportMail`, `MailTestMail`) use `App\Mail\Concerns\AddsPlainTextPart`, which adds a text/plain part made by `App\Support\PlainText::fromHtml()` (HTML-only mail is a spam signal). The compose screen shows a live preview (`preview` route rendered into an iframe) and sends `App\Mail\ClientTemplateMail` to the address typed in, with Reply-To `creatium.contact.email` and an optional PDF attachment (`attachment`, PDF only, up to 10 MB, not stored on the server; its name is kept in `client_emails.attachment_name` and shown in the history; the live preview skips the file). Every send is logged in `client_emails` (with the error on failure); if the email was started from an inquiry or project without `client_email`, the address is saved on it. Inquiry cards and the project page link to it with `?project=`.

**Outreach** (admin menu **Потенциални клиенти**, `Admin\OutreachController`, routes `admin.outreach.*`): businesses found by [Harvey](https://github.com/ethanplusai/harvey), which runs as a list-builder only, either on the owner's computer or on the server as the unprivileged `harvey` user (`deploy/harvey/install-harvey.sh`: systemd `harvey` + `harvey-dashboard` on 127.0.0.1:5555, and a daily `harvey-export.timer` that copies the CSV to `creatium.outreach.harvey_csv` = `storage/app/harvey/prospects.csv`; config and Windows guide in `tools/harvey/`; `tools/harvey/osm_categories.py` adds restaurants, salons, hotels, car repair, vets and physio to Harvey's free OpenStreetMap source, which otherwise refuses them). The admin can import that file with **Внеси от сървъра** or `php artisan creatium:outreach-import`. The admin uploads Harvey's `prospects.csv` (`App\Support\Outreach\Outreach::import`: dedup by email, skips invalid and suppressed addresses, updates only untouched rows) into `outreach_prospects`, then writes each first email by hand (a required observation in Bulgarian) and sends `App\Mail\OutreachMail`: a business-toned letter without images (table HTML + text part; who we are, the observation, links with `utm_source=outreach` to the site, the free website check and `/kontakti#konsultatsiya` as a „Запазете час за разговор“ button; lines of the observation starting with „– “ become a numbered list via `OutreachMail::observationParts()`), `List-Unsubscribe` + one-click headers, footer with legal data. It goes **only** through the separate `outreach` mailer (`config/mail.php`, `OUTREACH_MAIL_*`, `creatium.outreach.from_address`, set up with `deploy/configure-outreach-mail.sh`; a separate domain is safer, and a creatiumlab.com sender is accepted only after typing „да“ at a reputation warning, as the owners chose in October 2026); without it sending is blocked, never falling back to the main mailbox. Only `verified`/`risky` addresses, one email per business, `creatium.outreach.daily_limit` per day (default 20). Every send is logged in `client_emails.outreach_prospect_id`. **Click tracking** (no open pixel: inaccurate with Apple Mail, hurts deliverability and needs consent): the email's three links (`OutreachProspect::CLICK_LINKS`: site, check, booking) go through the signed `/o/{prospect}/{link}` (`OutreachClickController`, throttled), which records `clicked_at` (first), `last_clicked_at`, `click_count` and `last_click_link` and redirects to `OutreachMail::targets()` (the utm URLs). Not counted: logged-in users (our own previews), empty or bot/mail-scanner user agents, and clicks in the first minute after `sent_at`. The plain-text part keeps the clean URLs. The outreach list shows „Кликна: … · дата (n×)“ under the status and a **Кликнали** filter (`?clicked=1`, newest click first); the dashboard shows clicks in the last 7 days. The privacy pages describe the business data and click tracking under legitimate interest. **Follow-up**: one short second email (`OutreachFollowUpMail` extends `OutreachMail`, views `emails/outreach-followup*`, subject „Re: “ + the first subject, same mailer, tracked links and unsubscribe) to prospects in `OutreachProspect::dueForFollowUp()` (status `sent`, first email `creatium.outreach.followup_after_days` = `OUTREACH_FOLLOWUP_DAYS` (default 4) or more days ago, no `followup_sent_at`, not unsubscribed/suppressed, not converted to a lead); „Напомни“ per row (`admin.outreach.follow-up`) or „Напомни на всички“ (`admin.outreach.follow-up-all`, clicked first), counted in the daily limit and logged as `client_emails.template = outreach-followup`; the list has a **За напомняне** filter (`?followup=1`) and Днес shows how many are due. Clicks in the first minute after the follow-up are ignored too. **Статистика** (`/admin/statistika`, `Admin\StatsController`, 7/30/90/365 days): the email funnel (sent → clicked → replied or lead → won), the call funnel (called → answered → interest → won), leads by channel (to offer, won, lost), where leads stand now, and lost reasons. The signed `/otpisvane/{prospect}` (GET link and RFC 8058 POST, CSRF-exempt) adds the address to `outreach_suppressions` for good; imports and the admin cannot bring it back. Businesses Harvey found **without a website** (most of the OSM results) have no email, so they go to a call list instead: the export timer also runs `tools/harvey/export_no_website.py` (reads `harvey.db` read-only) into `creatium.outreach.harvey_no_website_csv` = `storage/app/harvey/no-website.csv`; the tab **Без сайт (за обаждане)** (`Admin\OutreachCallController`, routes `admin.outreach.calls.*`, model `OutreachCall`, `Outreach::importCalls`, or `creatium:outreach-import --calls`) lists them with `tel:` links (every number, mobile first), city/type/phone and mobile/landline filters (`is_mobile`, set on save from `OutreachCall::isMobileNumber()`: 087/088/089/098/099), a call status, a note and an optional „Обади се отново“ date (`callback_on`; a date today or earlier is cleared on save). **Следващо обаждане** (`admin.outreach.calls.next`, view `call-next` with `_call-script`, the owners' call script) walks `OutreachCall::queue()` one business at a time with the same filters: callbacks due today first, then `new`, then `no_answer` from earlier days with fewer than `MAX_NO_ANSWER` (2) attempts, mobile numbers first; „Запази и следващ“ saves and moves on, „Пропусни засега“ hides one for the session (`admin.outreach.calls.skip`). The current business is pinned in the URL (`?call=`), so a refresh keeps it, and the session remembers it (`outreach_calls_current`) when the page is opened again; **Назад към предишния** (`admin.outreach.calls.back`) pops the session history of saved/skipped businesses (last 50) and reopens one with `&back=1`, its recorded result pre-selected for correction. The list remembers its last filters and page in the session (opening it without a query redirects there; `?reset=1` clears, `?all=1` is the explicit „Всички“). A save with a result counts as one call per business per day (`called_at`, `attempts`; correcting it the same day does not add one); `_call-stats` shows today's calls by result against `creatium.outreach.daily_call_goal` (`OUTREACH_DAILY_CALL_GOAL`, default 40). Re-imports update name/phone/type/city by `external_id` and never touch status, note or callback. Harvey's own Scout only takes named people from team pages and skips role addresses, which finds almost nothing on small Bulgarian sites, so the export timer also runs `tools/harvey/find_site_emails.py` (Harvey's venv): for every company with a domain it reads the home page and up to three contact/about pages, keeps only the business's own address (its domain or a free mailbox such as abv.bg/gmail, never a third-party domain like the web agency in the footer, decodes Cloudflare-protected addresses), verifies it with Harvey's `_verify_candidate` (Reoon when `REOON_API_KEY` is set; a failed MX lookup is `guess`, never `invalid`), caches results in `site-emails.json` (30 days, 3 for `guess`) and writes `creatium.outreach.harvey_site_emails_csv` = `storage/app/harvey/site-emails.csv` in the prospects format; **Внеси от сървъра** imports both CSVs. `OutreachCall::isForeign()` drops businesses across the border (a non-+359 phone, or a Latin city that is not one of ours; the Ruse radius reached Giurgiu), and deletes already-imported ones that nobody has worked on.

**Business search** (tab **Търсене** under Потенциални клиенти, `Admin\OutreachSearchController`, routes `admin.outreach.search.*`; the main way to find prospects, Harvey is now optional): the admin picks a city and a business type (`App\Support\Outreach\BusinessSearch::CITIES` / `CATEGORIES`: OSM tags plus a Bulgarian Google query) and an `OutreachSearch` is created. Both sources keep **only businesses with a website** (the Overpass query requires a `website`/`contact:website`/`url` tag; Serper places without `website` are dropped). With `SERPER_API_KEY` (`services.serper.key`) the businesses come from Google Maps via `POST https://google.serper.dev/places` (`X-API-KEY`, `{q: "<query> <city>", gl: bg, hl: bg, page}`, up to 3 pages, `external_id` = `g:<cid>`); without it from OpenStreetMap, where few businesses have a website. **Изчисти и започни отначало** (`admin.outreach.search.reset`) deletes searches, businesses, the call list and prospects that were never emailed (`new`/`skipped`, no `sent_at`); emailed and unsubscribed prospects and all suppressions stay. The page then POSTs `work` repeatedly while it is open; `ProspectFinder::work()` does ~25 s per call under a cache lock (no queue worker or cron needed): first it runs the search (Overpass: three public mirrors; both sources fail with a readable message), stores each business once in `outreach_businesses` (by `external_id`, never re-processed by a later search), then per business `EmailFinder` reads the site and up to three contact/about pages through `SiteChecker::fetch()` (same SSRF protection as the website check) and keeps the business's own address (own domain or free mailbox, never a third-party domain; Cloudflare-encoded addresses decoded), falling back to the email tag in the map. `EmailVerifier` gives `published` when the domain accepts mail (MX/A), `guess` otherwise, or Reoon's verdict when `REOON_API_KEY` (`services.reoon.key`) is set; `invalid` is dropped. Found addresses become `OutreachProspect`s with `city` and `findings` (top three non-ok checks from `SiteChecker::check()`, fails first); businesses without an email are skipped (with `creatium.outreach.search_call_list` = `OUTREACH_SEARCH_CALL_LIST=true` those with a Bulgarian phone go to the call list instead; off by default since October 2026, at the owners' request). `OutreachProspect::suggestedObservation()` turns the findings into the email's observation (only real findings, rewritten for the owner by `FINDING_TEXTS`: what it is and what customers do because of it; when the site is fine, a Google/Maps visibility paragraph with the category query and city; `OutreachController::defaultSubject()` switches the subject the same way), pre-filled on the compose screen, and **Изпрати на избраните** (`admin.outreach.send-selected`) sends that text to the checked prospects through the same `deliver()` path as a single send (separate mailer, `canBeEmailed`, daily limit, `client_emails` log). `published` counts as sendable alongside `verified`/`risky`. **Checking unchecked prospects** (imported from Harvey as `guess`, or without findings): **Провери сайта и имейла на непроверените** on the outreach list POSTs `admin.outreach.check` repeatedly (~20 s per call under a cache lock; `php artisan creatium:outreach-check [--limit=]` does the same on the server). `App\Support\Outreach\ProspectChecker` runs the site check (top three findings, as in search) and confirms the email: it becomes `published` (or Reoon's verdict) only if the address is on the site's domain or a free mailbox **and** `EmailFinder::publishedOn()` finds it on the page Harvey saw (from `personalization`), the home page or the contact/about pages; otherwise it stays `guess` with a reason in `check_note` (third-party domain, not on the site, domain without mail, or a big platform from `ProspectChecker::PLATFORM_DOMAINS` such as notino.bg). `site_checked_at` marks a prospect as done (search-created prospects get it too), and a later Harvey import no longer overwrites a checked `email_status`.

## Deployment

Production is a Webdock VPS (AlmaLinux 9, Nginx, PHP-FPM, MariaDB, SELinux enforcing). Full guide: `DEPLOY-WEBDOCK.md` (general notes in `DEPLOY.md`). Scripts in `deploy/`:

- `almalinux-setup.sh`: one-time setup; safe to rerun.
- `configure-env.sh`: writes the production `.env` from the DB credentials in `/root/creatium-db.txt`.
- `deploy.sh`: pull, composer, npm build, migrate, seed, caches. Run it as the `deploy` user. It also runs automatically: `.github/workflows/deploy.yml` SSHes in after the **Tests** workflow passes on a push to `main` (not on the nightly run; it only warns and skips while the `DEPLOY_HOST` / `DEPLOY_SSH_KEY` / `DEPLOY_HOST_KEY` secrets are missing).
- `setup-auto-deploy.sh`: one-time, as `deploy`. It creates the GitHub SSH key, restricted in `authorized_keys` to running only `deploy.sh` (`restrict,command=`), and prints the secrets to add.
- `update-nginx.sh`: static-file caching plus security headers (`nginx-security.conf`: HSTS, a CSP that does not restrict scripts because GTM loads the marketing tags, X-Frame-Options, nosniff, Referrer-Policy). Nginx drops server-level `add_header` in any `location` with its own `add_header`, so the snippet is included at server level and in `/build/` and the static-file location. Run as root after pulling; it is not part of `deploy.sh`.
- `backup.sh`: DB + uploads backup.

PHP-FPM runs as the `deploy` user, so app files belong to `deploy`; don't reintroduce `chgrp`/group-based permissions. Run git and artisan on the server as `deploy`.
