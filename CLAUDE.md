# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Laravel 12 app that is two things at once:

- **The public site of Creatium Lab** (creatiumlab.com): an agency of three people (Борислав, Владимир, Мария) for small Bulgarian businesses: website build and monitoring, GEO/SEO, email campaigns. Bulgarian is the main language (root URLs), English lives under `/en`.
- **An internal admin panel** (`/admin`) for the team: leads, client projects, subscriptions, outreach, blog, editable texts. It started as a university "project management system", which is why the core model is `Project` with `Category` / `Technology` and the roles `admin` / `project-manager` / `developer` (all three can enter the admin; only `admin` manages users).

The two halves meet in one place: **every website form (contact, quote, website check, Kreo chat) becomes a `Project`** with `source = 'website'`, so leads sit next to client work. The admin is Bulgarian only (`lang/bg.json`, `lang/bg/pagination.php`).

Visual and copy rules for the public site are in `DESIGN.md`; read it before touching public views or text. Production deployment is in `DEPLOY-WEBDOCK.md`.

## Commands

```bash
composer install && npm ci          # dependencies
npm run build                       # Vite build -> public/build (Tailwind v4)
php artisan test                    # full suite (SQLite in memory, see phpunit.xml)
php artisan test --filter=DesignGTest              # one class or test
php artisan migrate:fresh --seed    # local: also seeds demo users + demo projects
php artisan creatium:make-admin you@example.com --name="Name" --profile=all   # create/promote an admin
```

Other commands: `creatium:test-mail`, `creatium:{telegram,facebook,linkedin}-connect`, `creatium:{facebook,linkedin}-publish`, `creatium:monitor-sites`, `creatium:outreach-import`, `creatium:outreach-check`.

- Local DB: `DB_CONNECTION=sqlite`, `DB_DATABASE=<abs path>/database/database.sqlite`. Demo login (local/testing only): `admin@projectmanager.com` / `password`.
- `npm run dev` writes `public/hot`; while it exists `@vite` points at the dev server and the built CSS is not used. **Never leave it on a server** (`deploy/deploy.sh` deletes it).
- Tests call `withoutVite()` (`tests/TestCase.php`), so no build is needed. CI (`.github/workflows/tests.yml`) runs the suite on PHP 8.2/8.3/8.4; `composer.json` pins `config.platform.php` to 8.2.0. `security-audit.yml` (weekly) never blocks a deploy.
- Because production runs `config:cache`, **read env only inside `config/*.php`**.

## Routing and middleware

- `routes/web.php`: public pages come from one `$publicPages` map registered for both languages. Bulgarian slugs at the root (`/uslugi`, `/paketi`, `/proekti`, `/za-nas`, `/kontakti`, `/vaprosi`, `/proverka-na-sait`, `/poveritelnost`, `/usloviya`, `/biskvitki`), English under `/en/...` with the same route names prefixed `en.`. Also `/uslugi/{slug}`, `/blog...`, `/prezentatsiya`, `/demo/{slug}`, `/izrabotka-na-sait-za-{slug}`, `/sitemap.xml`, `/robots.txt`, `/llms.txt`. **In views always link with `lroute('services')`** (`app/helpers.php`), never `route()`, so links keep the language.
- Global/web middleware (`bootstrap/app.php`): `RedirectToCanonicalHost` (prepended: in production `www.` 301s to the APP_URL host, and `AppServiceProvider` forces the root URL), `SetLocale` (first path segment `en` = English, else Bulgarian, also on 404), and appended to `web`: `DesignPreview`, `CaptureLeadAttribution`, `PublishBlogToFacebook`, `PublishBlogToLinkedIn`, `MonitorClientSites` (the last three do one step after the response, no cron). CSRF is off for `otpisvane/*` only (RFC 8058 one-click unsubscribe).
- Admin routes use `auth` + `admin` (`CheckAdminAccess`: any of the three roles); user management also needs `role:admin` (`RequireRole`). There is no public registration. Login, forms and heavy admin POSTs are throttled.

## Languages

`__('Bulgarian text')` is the key in views; `lang/en.json` maps it to English and a test fails if a translation is empty or still Cyrillic. Long legal pages have English views in `resources/views/en/` (`PageController::localized()`). The layout emits hreflang and the BG/EN switcher for routes that exist in both. Leads record `locale`; admin and the team email stay Bulgarian.

## Site content is data (the most important rule)

- `config/creatium.php` (Bulgarian) and `config/creatium_en.php` (English, same keys, missing keys fall back to Bulgarian) hold all copy: contact details, hero, services, `service_pages`, `contact_topics`, `contact_interests`, `plans`, `questions` (FAQ), `team`, `demos`, `industry_pages`, legal entity, `cookies`, GTM id, etc. **Views read content through `site('key')`, never `config()` directly.** Contact/legal values can be overridden by `CREATIUM_*` env vars (phones: `CREATIUM_PHONES`, comma separated; the G design shows one phone, `CREATIUM_G_PHONE`, through `g_phones()`).
- `App\Support\Content` (behind `site()`) returns the admin override from `content_blocks` (key + locale, cached, flushed on save), else the config. Only keys in `Content::BLOCKS` are editable (`home_hero`, `home_problem`, `home_engine`, `home_trust`, `home_process`, `home_contact`, `services_page`, `plans`, `questions`, `about`, `team`). The admin form is generated from the Bulgarian config structure, labels come from `Content::FIELD_LABELS` (unknown keys are shown as they are); lists of strings are "one per line", lists of arrays get add/remove, `*image` fields are uploads. `Content::withDefaults($key)` = the saved override plus config keys it lacks, so new keys appear after an older save; saved keys the config no longer has are harmless (`ContentRetiredKeysTest`).
- **Admin edits are never overwritten.** A change to copy in config does not reach saved overrides. When a default text changes, ship a migration that replaces **only whole strings that are exactly the old default**, copies the row to `<key>:backup-<date>` first (never overwriting a backup) and is skipped in tests (`App\Support\*2026` classes: `FinalPrices2026`, `DepositTerms2026`, `PlainCopy2026`, `GAudit2026`, `ConceptWording2026`, `IndustrySitesWording2026`, `PackagesCards2026`, `TeamMaria2026`, `TeamMariaTexts2026`, `AboutCopy2026`, `HeroOfferButton2026`, `PlanCaption2026`; the logic is tested directly). Keys that a `*2026` class or its test still mentions must stay in config. Some home keys are read dynamically (the presentation reads `home_engine.{tech,growth}_{tag,title,items}`), so grep for the key and for patterns like `$group . '_tag'` before deleting a field.
- Old retired keys (`hero`, `audience`, `process`, `services`, `packages`, `faq`) may still sit in `content_blocks`; nothing reads them.
- **Per-page SEO**: `content_blocks` key `seo:<route name>` for pages in `Content::SEO_PAGES`; posts have their own SEO fields. The layout prefers controller `$seo`, then the page override, then the view's `@section('title'/'meta_description')`; an overridden Meta Title is the whole `<title>`. Titles start with the search phrase, descriptions stay under ~155 characters, the layout drops „ | Creatium Lab“ past 60 characters. Controllers can pass `$pageAlternates` / `$hreflangAlternates` (routes with parameters) and `$noindex`.
- **JSON-LD** (`partials/breadcrumbs-ld`, `partials/home-ld`, FAQPage, Service): in Blade write the key as `'@' . 'context'` (a bare `@context` outside `@php` is compiled as a Blade directive and corrupts it); a test checks every sitemap page.
- **Copy rule (owners)**: no dashes (–, —, spaced hyphen) and no colons in visible site and email text, except clock times and URLs. The consultation is never called free (the free website check stays free). `PlainCopyTest` checks every sitemap page, the offers and the lead, consultation, outreach and site-check emails. Never claim results, reviews or clients that do not exist (the Google rating shows only when `creatium.google_reviews.count` > 0).
- **Uploads**: `App\Support\Uploads` stores images in `public/uploads/{blog,content,portfolio}` (jpg/png/webp/gif, 5 MB, no SVG) and only accepts back paths it created.

## Leads and forms

- **Contact form** (`HomeController@submitContact`, `partials/contact-form`): name, optional site, email, phone, `interests[]` (`creatium.contact_interests`), message, optional consultation slot, required consent, honeypot `website` (filled = fake success, nothing stored). Creates the `Project` lead (`status Planning`, category „Ново запитване“, attribution from the session, `leadDescription()` writes the interests), sends `NewLeadMail` to `creatium.notify_email` and stamps `email_sent_at` (a mail failure is logged and never loses the lead), sends Telegram, flashes `lead_created` for the GTM `generate_lead` event. Production `.env` starts with `MAIL_MAILER=log`: `bash deploy/configure-mail.sh`, then `creatium:test-mail`.
- **Consultation booking** (`partials/booking`, `#konsultatsiya`, `App\Support\Booking`): `creatium.booking.times` on the next working days from tomorrow (Sofia time), taken slots greyed, `resolve()` rejects anything else; the client gets `ConsultationBookedMail` with a Google Calendar link.
- **Quote form** (`partials/quote-form` at `/paketi#oferta`, `QuoteController`, throttled): `?paket=N` preselects a plan; required name, business, email or phone, consent; the rest optional; lead service „Оферта: <plan>“.
- **Website check** (`/proverka-na-sait`, `SiteCheckController`): a free lead magnet. A lead is created and, after the response (`defer()`), `SiteCheck\SendSiteCheckReport` runs `SiteAudit::run()` (home checks by `SiteChecker`, a breadth-first crawl by `SiteCrawler` limited by `site_check.crawl_limit` / `crawl_seconds`, optional PageSpeed with `PAGESPEED_API_KEY`, Google Shopping readiness for shops) and emails `SiteCheckReportMail`. Every request goes through `HostResolver` (public IPv4 only, pinned, redirects checked by hand, ports 80/443). Limits: 5 posts per IP per 10 minutes, 3 reports per email and 5 per domain a day. The report is saved in `projects.site_check_report`.
- **Bot protection**: Cloudflare Turnstile (`App\Support\Turnstile`, `partials/turnstile`) on the contact, quote and site-check forms, on only when `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` are set; if Cloudflare does not answer the request passes (no lead is lost), `success: false` or a missing token is rejected.
- **Attribution**: `CaptureLeadAttribution` keeps UTM, `gclid`/`fbclid` and the referrer in the session; `LeadAttribution::channel()` maps it to a channel label.
- **Telegram** (`Notify\Telegram`, `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`, `creatium:telegram-connect`, guide in `tools/telegram/README.md`) gets new leads and a prospect's first click, after the response; nothing is sent without settings.

## Admin panel

- **Profiles**: `users.profile` = `all` | `dev` | `sales` | `brand` (Борислав = dev, Владимир = sales, Мария = brand, the shared „Админ“ account = all). `App\Support\Admin\Profiles` is the single source of menus, the phone bottom nav, „+ Ново“ actions and the Днес sections. A profile only decides what is in the main menu and in Днес; nothing is locked: other sections sit in the collapsed „Всички раздели“ group (open on such a page) and in search (Ctrl+K), and permissions stay role based. `User::profile()` (null/unknown = `all`), `isMaster()`. Set in the Потребители forms and by `creatium:make-admin --profile=`.
- **Shell and styling**: `admin/layout` (ink sidebar with person and profile, header with crumb, search, „+ Ново“, „Нов дизайн“, bottom nav below 900px). Badge counts: `App\Support\Admin\Badges` (once per request). The admin loads only `resources/css/admin.css` (own Tailwind entry, `@source` for admin/auth views, components, `app/Models|Support|Http`; never `app.css` or `app.js`). Its `@theme` re-maps the palette the old views use to design G, and unlayered rules style forms, tables, badges, pagination, EasyMDE and `adm-flash`; new markup uses `adm-*` / `td-*` classes. Buttons: `adm-btn` (ink, primary), `adm-btn ghost` (outlined secondary), `sm`; accent red is for links and alerts, green only for done/paid states. The admin is light only. A bare `@php(...)` next to a `@php ... @endphp` block in the same Blade file swallows the code between them: use block form.
- **Днес** (`/admin/dnes`, `TodayController`, `Admin\Today`, `Admin\TodayBlocks`, `TeamActivity`): the landing page. Tabs per person and „Целият екип“ (`?user=ID|all`); a numbers strip, then blocks for the profile of that person: dev = projects in progress, subscribers with site/payment trouble, new site checks, leads with next steps, system warnings; sales = consultations, new inquiries, due steps, calls vs goal and first emails vs limit, clicked prospects, follow-ups, leads without a next step; brand = scheduled posts and drafts, Facebook/LinkedIn state, LinkedIn due, review replies, monthly reports to send, recent client emails. All shows a compact overview plus „Направено днес“. Blocks show 3 to 7 rows with direct actions.
- **Sections**: Табло (`AdminController::dashboard`, `SalesMetrics`); Запитвания and Проверки на сайт (`InquiryController`); Проекти (`Project::clientProjects()`: admin-created projects and won leads); Абонаменти (`ClientController`); Имейли до клиенти; Чат разговори; Потенциални клиенти; Статистика; Отговори на отзиви; Блог; Текстове; SEO; Категории; Технологии; Потребители; Здраве на системата (`HealthController`, `Admin\SystemHealth` shared with Днес); Търсене (`SearchController`, phones match on digits).
- **Sales pipeline**: leads have `stage` (`Project::STAGES`: new, contacted, offer, won, lost; `OPEN_STAGES` the first three), `stage_changed_at`, `next_action` + `next_action_at` (stored UTC, entered in Sofia time), `lost_reason`, `assigned_to`. The partial `admin/projects/_pipeline` (inquiry cards, project page, Днес) PATCHes `admin.projects.pipeline`: won moves a `Planning` project to `In Progress`, lost sets `Cancelled`, both clear the next step. History is `project_notes` (note / call / stage); the project page timeline is `ProjectController::timeline()`. Project statuses are stored in English (`Planning`, `In Progress`, `Completed`, `On Hold`, `Cancelled`) and shown through `Project::STATUSES` / `statusLabel()` / `statusClass()`. `Admin\LeadConverter` turns a prospect, a call or a LinkedIn contact into a lead (`source = 'outreach'`, stage `contacted`) and links it back (a second click opens the same lead).
- **Subscriptions and monitoring**: a project with `monthly_fee` > 0 (not Cancelled) is a subscriber (`Project::subscribers()`). `client_payments` (one per YYYY-MM) and `Project::paymentState()` (paid / upcoming / late, Sofia time) drive Абонаменти, the badge and Днес. `Admin\SiteMonitor` checks subscribers with a `website_url` at most every 6 h (response, SSL and domain expiry) through the `MonitorClientSites` middleware or `creatium:monitor-sites`; problems show on Абонаменти and Днес and Telegram gets an alert (at most once a day per problem). The `monthly-report` email template is linked from each subscriber.
- **Emails to clients** (`ClientEmailController`, `App\Support\ClientEmails`, views in `resources/views/emails/client/`): `inquiry-reply`, `offer-start`, `offer-active`, `offer-individual`, `demo-site`, `monthly-report`. Offers are grouped editable fields (`ClientEmails::groups()`; an empty optional field hides its block; `ClientEmails::fill()` makes `{client_name}` and `{business}` work anywhere). The compose screen has a live preview, an optional PDF (not stored, 10 MB) and „Използвай отново“ (`?from=<id>`); every send is logged in `client_emails`. Mailables without a text view use `Mail\Concerns\AddsPlainTextPart` (HTML-only mail is a spam signal).
- **Review replies** (`Reviews\ReviewReplyWriter`): a pasted Google review becomes a draft to edit and publish by hand; Claude via `anthropic-ai/sdk` (`ANTHROPIC_API_KEY`), a star-based template without a key or on error; the prompt forbids invented promises.

## Outreach, search, calls, LinkedIn

- **Outreach list** (`OutreachController`, `Outreach\Outreach`): prospects (`outreach_prospects`) come from the business search, from Harvey CSV imports (optional list-builder, `deploy/harvey/`, `tools/harvey/`, `creatium:outreach-import`) and are emailed one by one with a hand-written observation (`OutreachProspect::suggestedObservation()` pre-fills it from real findings). `OutreachMail` goes **only** through the separate `outreach` mailer (`OUTREACH_MAIL_*`, `creatium.outreach.from_address`, `deploy/configure-outreach-mail.sh`); without it sending is blocked, never falling back to the main mailbox. Only `verified` / `published` / `risky` addresses, one email per business, `outreach.daily_limit` per day (20), `List-Unsubscribe` + one-click headers. Every send is logged in `client_emails.outreach_prospect_id`.
- **Tracking**: the three links of the email go through the signed `/o/{prospect}/{link}` (`OutreachClickController`), which records the click and redirects; no open pixel. Logged-in users, bots and clicks in the first minute are not counted. The signed `/otpisvane/{prospect}` adds the address to `outreach_suppressions` for good. **Follow-up**: one short second email (`OutreachFollowUpMail`) after `outreach.followup_after_days` (4) to prospects without a reply.
- **Business search** (`OutreachSearchController`, `Outreach\BusinessSearch`, `ProspectFinder`, `EmailFinder`, `EmailVerifier`, `ProspectChecker`): city + business type; Google Maps via Serper (`SERPER_API_KEY`) or OpenStreetMap; keeps only businesses with a website and a published own-domain or free-mailbox email (fetched through `SiteChecker::fetch()`). The page POSTs `work` repeatedly while open (no queue or cron).
- **Calls** (`OutreachCallController`, `OutreachCall`): businesses without a website go to a call list (filters, status, note, callback date). **Следващо обаждане** walks `OutreachCall::queue()` (callbacks due today, new, then no-answer with fewer than 2 attempts, mobile first); keys 1 to 4 set the result, Enter saves and moves on, S skips, B goes back. A save with a result counts as one call per business per day against `outreach.daily_call_goal` (40).
- **LinkedIn** (`LinkedinController`, `LinkedinProspect`): LinkedIn forbids scraping, so the team searches by hand and the admin only tracks (nothing is fetched from or sent to LinkedIn). Profiles are added by URL (`normalizeUrl()`), moved along found, invited, connected, messaged, replied, not_interested (`moveTo()` fills earlier dates once and records who), with a next-step date, an assignee, the daily invite goal (`linkedin_daily_invites`, 15) and „→ Запитване“.

## Kreo chat

`partials/chat-widget`, `ChatController` (POST `/chat`, throttled; restores `/chat/{uuid}`), `Chat\ChatAssistant`. Provider by `creatium.chat.provider` (`auto`: Claude with `ANTHROPIC_API_KEY`, else Mistral with `MISTRAL_API_KEY`). Both get the site content from `Chat\SiteKnowledge::text()` (about, the team as owners (the first two members) and colleagues, solution, services, plans, FAQ, demos, contacts) and one strict tool `save_contact` that `ChatLeads::save()` turns into a lead (service „Запитване от чата“, one per conversation). Claude history is stored as returned in `chat_conversations.api_messages` (append only, a refused turn is not stored); Mistral history is the last 12 visible messages (use `reorder()`: the relation is ordered by id ascending). Without a key, on error or refusal, or over `chat.daily_limit` (300 a day), `Chat\FaqResponder` answers from the FAQ and built-in topics. A conversation is capped at 30 messages and pruned after 30 days (`ChatConversation::prune()`). The assistant must never present the industry sites as clients.

## Blog and autopost

`Post` / `PostCategory` store translatable fields as JSON by locale (`HasTranslations`: `$post->tr('title')`, `trOrBg()`); a language exists only when its title is filled; `Post::visible($locale)` = published, `published_at` in the past, title and slug present. Slugs are Latin (`Str::slug(..., 'bg')`), bodies are Markdown (`html_input => strip`), the editor is EasyMDE (`resources/js/admin-editor.js`, image upload via `admin.uploads.image`). `BLOG_ENABLED=false` makes the public routes 404. While no post has English, `/en/blog` points to the Bulgarian blog and is `noindex`. Starter articles come from `database/data/*.php` through migrations (`StarterBlogPosts`, never overwriting edits; links between articles point only to earlier ones, never to drafts).

- **Facebook** (`Facebook\FacebookPublisher`, `FACEBOOK_PAGE_ID` / `FACEBOOK_PAGE_TOKEN` via `creatium:facebook-connect`, guide in `tools/facebook/README.md`) and **LinkedIn** (`LinkedIn\LinkedInPublisher`, `LINKEDIN_ORGANIZATION_ID` / `LINKEDIN_ACCESS_TOKEN` / `LINKEDIN_TOKEN_EXPIRES`, the token lives 60 days, `creatium:linkedin-connect`, guide in `tools/linkedin/README.md`) share one design: visible Bulgarian posts from the last 2 days go out at once, older ones one per day 09:00 to 20:00 Sofia time, oldest first. The deferred middleware runs one step at most every 10 minutes. `posts.*_post_id`, `*_posted_at`, `*_error` record the result; a failed post is not retried automatically; a bad token (Facebook 190, LinkedIn 401) pauses posting for 12 h; LinkedIn sends nothing after `token_expires`. The admin Блог list, Днес and Здраве на системата show the state with „Пусни сега“ / „Опитай пак“.

## Tracking and consent

GTM + Consent Mode v2: `creatium.gtm_id` (`GTM_ID`, defaults to the real id only when `APP_ENV=production`, empty disables it). `partials/gtm-head` sets consent defaults to denied, re-applies a stored choice (`creatium-consent`, 12 months) and loads GTM 2.5 s after `load` or at the first interaction; `partials/cookie-consent` is the category banner. GA4, Clarity and ad pixels live inside GTM (marketing partner), never in the code. `GOOGLE_SITE_VERIFICATION` adds the Search Console tag. **Bing**: `creatium.bing_site_verification` (two codes baked in, more via `BING_SITE_VERIFICATION`) is output on every public page and `public/BingSiteAuth.xml` lists the same codes; keep both in sync and do not remove them or Bing drops the verification. The privacy and cookie pages switch their text on `gtm_id`.

## Portfolio, industry pages, presentation

- **/proekti** shows projects with `is_public = true` and status `Completed` (admin checkbox and optional `screenshot`; the card text is the project `description`, so write it for the public) followed by the ten industry sites (`creatium.demos`: `restorant`, `kashta-za-gosti`, `salon`, `fitnes`, `dentalen-centar`, `advokatska-kantora`, `avtoservis`, `pokrivi`, `nedvizhimi-imoti`, `onlain-magazin`). Each is a standalone Bulgarian page at `/demo/{slug}` (`DemoController`, `resources/views/demos/`, shared `_layout`, `noindex`, `resources/css/demos.css`). The businesses are fictional but **nothing public says so**: no „Концепция“, „демо“, „примерен“, „измислен“ on the sites or cards (`DemoSitesTest`); „демо“ stays only in the offer wording for the client's own pre-launch preview. `<x-demo-photo>` shows `public/images/demos/{slug}/{name}.webp` when the file exists, else an SVG slot. Card screenshots are `public/images/demos/{slug}.webp` (960×600, plus `-640` / `-480` for `demo_srcset()`): re-shoot them when a page's top changes.
- **Industry pages** `/izrabotka-na-sait-za-{slug}` (`PageController::industry`, `creatium.industry_pages`, Bulgarian only) reuse the problems, solutions, package and FAQ of their demo, with Service + FAQPage JSON-LD.
- **Services**: `service_pages` (`website`, `seo`, `google`, `email`, `support`, `shopping`; per language slug, title, lead, includes, result, `package` = index into `plans.items`, FAQ). `shopping` has no price (owners have not set one: „Цена по оферта“). The pages feed the sitemap, `/llms.txt` and Kreo.
- **Presentation** (`/prezentatsiya`, `/en/presentation`, noindex): ten 1600×900 slides from the same content blocks. The PDFs in `public/files/` are static: when copy or prices change, regenerate them with `tools/presentation/render.mjs` against a local `php artisan serve` (after `npm run build`) and commit them.

## Frontend

Tailwind v4 via Vite; brand tokens and custom utilities in `resources/css/app.css` (current design). Icons are inline SVG, `<x-icon name="...">`, paths in `App\Support\Icons::ICONS` (Font Awesome Free solid paths; no package). The public layout inlines the built CSS when `creatium.inline_css` is true; the admin links it. The public layout supports light and dark (`.dark` on `<html>` from `creatium-theme`), so every new current-design view needs `dark:` classes (see `DESIGN.md`).

## Deployment

Production is a Webdock VPS (AlmaLinux 9, Nginx, PHP-FPM, MariaDB, SELinux enforcing); see `DEPLOY-WEBDOCK.md`. Scripts in `deploy/` (`almalinux-setup.sh`, `configure-*.sh`, `backup.sh`, `harvey/`): `deploy.sh` (pull, composer, npm build, migrate, seed, caches; run as `deploy`; `.github/workflows/deploy.yml` runs it over SSH after **Tests** pass on `main`, skipped while the `DEPLOY_*` secrets are missing), `setup-auto-deploy.sh` (restricted key for it), `update-nginx.sh` (static caching and security headers; run as root after pulling, not part of `deploy.sh`; Nginx drops server-level `add_header` in a `location` with its own, so the snippet is included in `/build/` and the static location too). PHP-FPM runs as `deploy`: app files belong to `deploy`, no group permissions; run git and artisan as `deploy`.
