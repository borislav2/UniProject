This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Laravel 12 app that is two things at once:

- **The public site of Creatium Lab** (a two-person agency for small Bulgarian businesses: website build and monitoring, GEO/SEO, email campaigns), live at creatiumlab.com. Bulgarian is the main language (root URLs); an English version lives under `/en`.
- **An internal admin panel** (`/admin`) for managing client projects. It started as a university "project management system", which is why the core model is `Project` with `Category` / `Technology` and roles `admin` / `project-manager` / `developer`.

The admin is in Bulgarian (`lang/bg.json` and `lang/bg/pagination.php` for pagination). Its menu (`admin/layout`) is grouped Клиенти / Продажби / Сайт / Настройки, with badges for unread inquiries and call-backs due today. The dashboard (`AdminController::dashboard`, numbers from `App\Support\Admin\SalesMetrics`) also shows this month against last month up to the same day (leads, contacted, offers, won, lost, win rate), open leads by stage with how many lack a next step or a person, response time (lead created → first note or email, last 30 days), leads by kind, and a team table (open, new and overdue leads per person, this week's calls, emails, outreach emails, stage changes, won this month). It shows what needs doing today: unread inquiries, calls today against the goal (`OutreachCall::todayStats()`), first emails sent today against the limit, Крео chats in the last 7 days, the latest leads with `tel:` links, consultations in the next two weeks, projects in progress, the next scheduled blog post and leads by channel. Project statuses are stored in English (`Planning`, `In Progress`, `Completed`, `On Hold`, `Cancelled`, validated that way) and shown through `Project::STATUSES` / `statusLabel()` / `statusClass()`; `serviceLabel()` turns a `contact_topics` key into its text. **Sales pipeline**: website leads (contact form, Крео, website check) get a `stage` (`Project::STAGES`: new → contacted → offer → won / lost, set to `new` on create; `OPEN_STAGES` are the first three), `stage_changed_at`, a `next_action` text with `next_action_at` (stored UTC, entered in Sofia time) and a `lost_reason`. `partials` `admin/projects/_pipeline` (on inquiry cards, the project page and **Днес**) PATCHes `admin.projects.pipeline`; won moves a `Planning` project to `In Progress`, lost sets `Cancelled`, both clear the next step. **Днес** (`/admin/dnes`, `TodayController`, `App\Support\Admin\Today`) is per person (tabs for each user and „Целият екип“, `?user=ID|all`, default the logged-in user: their leads plus unassigned ones) with „Направено днес“ from `App\Support\Admin\TeamActivity` (notes, stage changes, client emails, outreach emails and calls; `outreach_calls.called_by` records who called); it is the first menu item and where login lands: consultations today/tomorrow, unread leads with how long they wait, next steps due today or overdue, prospects who clicked in the last 7 days, and open leads without a next step; its badge counts unread + due + call-backs. Leads can be assigned (`projects.assigned_to`, „Води го“ in the pipeline panel); Днес has „Моите и неразпределените“ (`?mine=1`) and the project list a „Моите“ filter. **Search** (`/admin/tarsene`, `Admin\SearchController`, box in the header, Ctrl+K): leads/projects, prospects, calls, Крео chats and posts; phones match on digits (last 9). **Phone**: a bottom menu (Днес, Запитвания, Обаждания, Търсене, Меню) below `md`, and `public/admin.webmanifest` (start `/admin/dnes`, icons `images/icon-192/512.png`) so the admin can be added to the home screen. The next-call screen takes keys 1–4 (result), Enter (save and next), S (skip), B (back). **Здраве на системата** (`/admin/zdrave`, `Admin\HealthController`): mail, Telegram, outreach mailbox, Serper, Reoon, Крео provider, Facebook, GTM, monitored client sites, debug mode, URL, last build, free disk, storage, last backup in `/var/backups/creatium`, each with the command that fixes it. The dashboard shows a red banner for overdue steps. **History** (`project_notes`, `ProjectNote`: note / call / stage): the pipeline panel takes an optional call note and logs stage and next-step changes; the project page has an „История“ form and a timeline built by `ProjectController::timeline()` (creation and channel, notes, `client_emails`, the Крео chat by `lead_id`, a linked prospect's first email and clicks). **Converting** (`App\Support\Admin\LeadConverter`): „→ Запитване“ on a prospect (`admin.outreach.lead`) or a call (`admin.outreach.calls.lead`, also on the next-call screen) creates a `Project` with `source = 'outreach'`, stage `contacted`, channel „Писма до бизнеси“ / „Обаждания“ and the contact details, and links it back (`project_id` on `outreach_prospects` / `outreach_calls`; a second click opens the same lead). Prospects now store the business `phone` from the map search. **Subscriptions** (admin **Абонаменти**, `/admin/abonamenti`, `Admin\ClientController`): a project with `monthly_fee` > 0 (and not Cancelled) is a subscriber (`Project::subscribers()`), with `package` and `billing_day` set in the project form. `client_payments` (one per `period` „YYYY-MM“) and `Project::paymentState()` (Sofia time; paid / upcoming / late, an unpaid previous month counts as late) drive the page (monthly revenue, paid this month, late, „Платено за …“ = `admin.clients.paid`, which also writes a note), the menu badge, Днес and the dashboard revenue. **Site monitoring** (`App\Support\Admin\SiteMonitor`): subscribers with a `website_url` are checked at most every 6 h (response via `SiteChecker::fetch()`, SSL expiry from the certificate, domain expiry from RDAP, none for .bg) by the `MonitorClientSites` web middleware (one tick per 15 min after the response, up to 3 sites; no cron) or `php artisan creatium:monitor-sites [--all]` / „Провери сега“; results go to `monitor_*`, `ssl_expires_at`, `domain_expires_at`, problems (down, SSL or domain within 14 days) show on Абонаменти and Днес, and Telegram gets an alert when a site goes down and at most once a day while a problem lasts. **Monthly report**: the `monthly-report` template in Имейли до клиенти (done / results / site status / next month, one item per line), linked from each subscriber with the site status pre-filled. `<x-phone>` (`App\Support\Phone`) renders a `tel:` link plus Viber and WhatsApp links in the 359… format. **Telegram** (`App\Support\Notify\Telegram`, `services.telegram.*` = `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`, set by `php artisan creatium:telegram-connect`, guide in `tools/telegram/README.md`; `.env` writing shared with Facebook in `App\Support\EnvFile`) gets new leads (form, Крео, website check, with the consultation time) and a prospect's first click (plus any booking click), sent after the response; without settings nothing is sent. The project list (**Проекти**) shows only client work (`Project::clientProjects()`: projects created in the admin and leads at stage `won`; open and lost leads live in Запитвания / Проверки на сайт, and the old `?filter=leads` redirects there) with the filters В работа / Завършени / Моите (`?filter=active|done|mine`), and its search also matches the client's phone and email. The project page shows the client's phone, email, site and consultation at the top, and the edit form has client phone and email fields.

The two halves meet in one place: **a contact-form submission becomes a `Project`** (`source = 'website'`, status `Planning`, category "Ново запитване"), so leads show up in the admin list next to real client work.

Visual and copy rules live in `DESIGN.md`; read it before touching views or text. The site follows a technical specification from the marketing partner (Владимир Цончев); GTM + Consent Mode, BG/EN and the CMS (blog, editable texts, per-page SEO) are all built.

## Commands

```bash
composer install && npm ci          # dependencies
npm run build                       # Vite build -> public/build (Tailwind v4)
php artisan test                    # full suite (SQLite in memory, see phpunit.xml)
php artisan test --filter=test_contact_form_creates_lead_and_notifies_team   # one test
php artisan test tests/Feature/MarketingTest.php                              # one file
php artisan migrate:fresh --seed    # local: also seeds demo users + demo projects
php artisan creatium:make-admin you@example.com --name="Name"   # create/promote an admin
```

Local DB: set `DB_CONNECTION=sqlite` and `DB_DATABASE=<abs path>/database/database.sqlite` in `.env`. Demo logins (local/testing only): `admin@projectmanager.com` / `password`.

`npm run dev` (and `composer dev`, which runs it) writes `public/hot`; while that file exists `@vite` points at the dev server and the built CSS is not used. Never leave it on a server (`deploy/deploy.sh` deletes it).

CI (`.github/workflows/tests.yml`) runs `php artisan test` on PHP 8.2/8.3/8.4 after copying `.env.example` (`composer.json` pins `config.platform.php` to 8.2.0, so `composer update` never locks a package that needs a newer PHP); tests call `withoutVite()` (see `tests/TestCase.php`), so no build is needed for tests. `.github/workflows/security-audit.yml` runs `composer audit --locked` and `npm audit` every Monday, on demand and when a lock file changes (separate from Tests, so it never blocks a deploy; a failure means: update the named package and run the tests). `.github/dependabot.yml` sets `open-pull-requests-limit: 0`, so Dependabot opens only security-fix PRs (when „Dependabot security updates“ is on in the repo settings).

## Architecture

**Routing** (`routes/web.php`): public pages are registered from one `$publicPages` map for both languages. Bulgarian uses Bulgarian slugs at the root (`/uslugi`, `/paketi`, `/proekti`, `/za-nas`, `/kontakti`, `/poveritelnost`, `/usloviya`, `/biskvitki`); English uses `/en/...` with English slugs and the same route names prefixed `en.`. In views always link with `lroute('services')` (from `app/helpers.php`), never `route()`, so links stay in the current language. Dynamic `/sitemap.xml` (both languages with hreflang alternates) and `/robots.txt` come from `PageController`. `/about` and `/contact` 301-redirect. In production `RedirectToCanonicalHost` (prepended globally) 301-redirects `www.` + the APP_URL host to APP_URL with the same path and query, and `AppServiceProvider` forces the root URL to APP_URL, so canonical/hreflang/sitemap never point at www (Nginx answers both hosts; Google had indexed www pages as duplicates). There is **no public registration**; accounts come from `creatium:make-admin` or the admin Users screen. Admin routes use `auth` + `admin` (`CheckAdminAccess`: any of the three roles); user management additionally needs `role:admin` (`RequireRole`). Login and the contact POST are throttled.

**Languages**: the global `SetLocale` middleware sets the locale to `en` when the first path segment is `en`, otherwise `bg` (this also covers 404 pages). Views wrap UI text as `__('Bulgarian text')`; `lang/en.json` maps it to English, and a test fails if a translation is empty or still Cyrillic. Long legal pages have separate English views in `resources/views/en/` (`PageController::localized()`). The layout outputs hreflang links and the BG/EN switcher for any route that exists in both languages. Leads record `locale`; admin and the notification email stay Bulgarian and always store the Bulgarian service label.

**Site content is data, not markup.** `config/creatium.php` holds contact details, hero and audience copy, services, `contact_topics` (the form's service dropdown), process steps, packages/prices, FAQ, team, industries, legal entity data, `gtm_id`, `google_site_verification`, the `cookies` list shown on `/biskvitki`, `inline_css` and `notify_email`. English versions of the content keys are in `config/creatium_en.php` (same keys; missing keys fall back to Bulgarian). Views read content through `site('services')`, never `config()` directly. `contact_topics` is keyed (`new-system`, `modernization`, `support`): the key is the form value, the label is per language. In Blade templates write the JSON-LD key as `'@' . 'context'` (a bare `@context` outside `@php` blocks is compiled as Laravel's `@context` directive and corrupts the key); `test_every_structured_data_block_is_valid_json_with_the_schema_org_context` checks every sitemap page. The layout drops „ | Creatium Lab“ when the title would exceed 60 characters (the website check flags longer titles), and a controller can pass `$noindex` (used by `/en/blog`, which has no hreflang pair or sitemap entry while no post has English).
- **Uploads**: `App\Support\Uploads` stores images in `public/uploads/{blog,content}` (jpg/png/webp/gif, 5 MB, no SVG) and only accepts back paths it created.
- **Profile**: `/admin/profile` lets each user change name, email and password (current password required).

**Seeders** are idempotent (`firstOrCreate`). `DatabaseSeeder` only seeds roles/categories/technologies in production; demo users and projects are limited to `local`/`testing`.

## Deployment

Production is a Webdock VPS (AlmaLinux 9, Nginx, PHP-FPM, MariaDB, SELinux enforcing). Full guide: `DEPLOY-WEBDOCK.md` (general notes in `DEPLOY.md`). Scripts in `deploy/`:

- `almalinux-setup.sh`: one-time setup; safe to rerun.
- `configure-env.sh`: writes the production `.env` from the DB credentials in `/root/creatium-db.txt`.
- `deploy.sh`: pull, composer, npm build, migrate, seed, caches. Run it as the `deploy` user. It also runs automatically: `.github/workflows/deploy.yml` SSHes in after the **Tests** workflow passes on a push to `main` (not on the nightly run; it only warns and skips while the `DEPLOY_HOST` / `DEPLOY_SSH_KEY` / `DEPLOY_HOST_KEY` secrets are missing).
- `setup-auto-deploy.sh`: one-time, as `deploy`. It creates the GitHub SSH key, restricted in `authorized_keys` to running only `deploy.sh` (`restrict,command=`), and prints the secrets to add.
- `update-nginx.sh`: static-file caching plus security headers (`nginx-security.conf`: HSTS, a CSP that does not restrict scripts because GTM loads the marketing tags, X-Frame-Options, nosniff, Referrer-Policy). Nginx drops server-level `add_header` in any `location` with its own `add_header`, so the snippet is included at server level and in `/build/` and the static-file location. Run as root after pulling; it is not part of `deploy.sh`.
- `backup.sh`: DB + uploads backup.

PHP-FPM runs as the `deploy` user, so app files belong to `deploy`; don't reintroduce `chgrp`/group-based permissions. Run git and artisan on the server as `deploy`.
